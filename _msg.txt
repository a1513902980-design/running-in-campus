geo_guard: 默认关闭保持期（它会污染主轨迹，实测导致服务端拒绝）

事故（2026-10-18，真实一轮 2.2 km）：
- 判定页 4/4 全过、载荷 9/9 自洽、地理闸门也过，提交后服务端却给
  isvalidreason=2（代码表：超过指定运动时间）
- 但本轮 dltime 只有 17:02，而学校配置 boy_min_time=12 / boy_max_time=45，
  根本不该判"超过"
- 查 guard 心跳：通过=18 从头到尾没变，保持拦截累计 3600
  => 保持期把锚点"冻死"在起点，真实轨迹点走出 100 m 后全被判"另一路定位源"
- 后果不是防住假点，而是**进入数据模型的坐标被污染成固定值**：
  上游 App 用"坐标×时间"算有效运动时间，位置被冻死 => 时长规则误判
- 更阴：里程仍正常涨（喂点走另一条入口没被拦），
  所以"判定页全过"与"服务端拒绝"能同时成立

修法：
- 新增 STRICT_MODE，默认 false：生产只保留防线①（越界半径），
  其余原样放行并跟走锚点，绝不动正常轨迹
- 防线②③降级为可选（true 才启用）
- 心跳增加"模式"字段，并同时给出被放行点数，
  这样"在拦"和"拦对了没"可以一起判断
- README 补上完整事故说明与该结论：
  「防伪影」的代价不能是污染主数据；兜底应放在提交前，而不是运行期改数据

验证：改完重跑同账号同里程，服务端返回 reason='' / result=1 / 提交成功待审核。
